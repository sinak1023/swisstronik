# پنل مدیریت بازو (Bale Bot)

پنل وب برای مدیریت یک بازوی بله (Bale bot) که با استفاده از آن می‌توانید:

- با نام کاربری/رمز عبور وارد پنل شوید (نشست شما تا زمانی که روی «خروج» نزنید منقضی نمی‌شود).
- توکن بازو را وارد کرده و بازو را بارگذاری/تایید کنید (`getMe`).
- فایل CSV حاوی شناسه‌های عددی کاربران (chat_id) را آپلود کرده، ستون شناسه را انتخاب و ردیف‌های موردنظر را انتخاب/حذف کنید.
- پیام متنی (با پشتیبانی از لینک به‌صورت Markdown)، عکس یا فایل را برای کاربران انتخاب‌شده ارسال کنید.
- روند ارسال را با نوار پیشرفت و لاگ لحظه‌ای (از طریق Socket.IO) دنبال کنید.

## پیش‌نیاز

- Node.js نسخه ۱۸ به بالا (برای `fetch`/`FormData` داخلی).

## راه‌اندازی

```bash
cd bot-dashboard
npm install
cp .env.example .env
npm run hash-password -- "رمز-عبور-دلخواه"
# مقدار ADMIN_PASSWORD_HASH چاپ‌شده را در فایل .env قرار دهید
npm start
```

سپس مرورگر را روی `http://localhost:3000` باز کنید.

## متغیرهای محیطی (`.env`)

| متغیر | توضیح |
|---|---|
| `PORT` | پورت اجرای سرور (پیش‌فرض ۳۰۰۰) |
| `SESSION_SECRET` | کلید امضای نشست‌ها؛ حتماً در production یک رشته تصادفی طولانی قرار دهید |
| `ADMIN_USERNAME` | نام کاربری ورود به پنل |
| `ADMIN_PASSWORD_HASH` | هش bcrypt رمز عبور (با `npm run hash-password -- "..."` بسازید) |
| `COOKIE_SECURE` | روی `true` بگذارید اگر سرویس پشت HTTPS اجرا می‌شود |
| `BROADCAST_DELAY_MS` | فاصله پیش‌فرض بین ارسال هر پیام (میلی‌ثانیه) برای جلوگیری از rate limit |

## نکات فنی

- **API بازو**: از `https://tapi.bale.ai/bot<token>/<method>` استفاده می‌شود (`getMe`, `sendMessage`, `sendPhoto`, `sendDocument`)، مطابق مستندات https://docs.bale.ai/.
- **نشست همیشگی**: کوکی نشست با `rolling: true` و انقضای ~۱۰ سال تنظیم شده تا در عمل تا زمان کلیک روی «خروج» منقضی نشود.
- **توکن بازو در نشست**: توکن در نشست سمت سرور (نه در مرورگر) نگه‌داری می‌شود و طبق درخواست، پس از هر ورود مجدد باید دوباره وارد و تایید شود.
- **بهینه‌سازی ارسال فایل/عکس**: فایل ضمیمه فقط برای اولین گیرنده آپلود می‌شود؛ `file_id` بازگشتی از بله برای باقی گیرندگان استفاده می‌شود تا حجم/زمان ارسال کاهش یابد.
- **مدیریت خطای ۴۲۹ (Too Many Requests)**: در صورت پاسخ ۴۲۹ از API بله، ارسال با توجه به `retry_after` به‌صورت خودکار تا ۳ بار تلاش مجدد می‌شود.
- **ذخیره‌سازی**: فایل‌های آپلودی و وضعیت ارسال‌ها فقط در حافظه (in-memory) نگه‌داری می‌شوند - برای استفاده تک‌کاربره/ادمین مناسب است و نیازی به دیتابیس ندارد.
- **تحمل خطا در حین ارسال گروهی**: اگر کاربری بازو را بلاک/استاپ کرده باشد یا هر خطای دیگری برای یک گیرنده رخ دهد، فقط همان گیرنده در لاگ «ناموفق» ثبت می‌شود و ارسال برای بقیه کاربران بدون وقفه ادامه پیدا می‌کند؛ کل فرآیند/سرور متوقف نمی‌شود.
- **مدیریت خطاهای عمومی سرور**: آپلود فایل بیش از حد مجاز، مسیرهای نامعتبر و خطاهای پیش‌بینی‌نشده در میان‌افزارها به‌صورت JSON مدیریت می‌شوند؛ `uncaughtException`/`unhandledRejection` هم لاگ می‌شوند تا پردازه در وضعیت نامعتبر باقی نماند (به کمک systemd پایین دوباره بالا می‌آید).

## اجرا به‌صورت سرویس (systemd)

فایل نمونه `deploy/bale-bot-dashboard.service` را به `/etc/systemd/system/` کپی کنید، مقادیر `WorkingDirectory` و `User` را مطابق سرور خودتان اصلاح کنید، سپس:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now bale-bot-dashboard
sudo systemctl status bale-bot-dashboard
journalctl -u bale-bot-dashboard -f
```

با `Restart=always` در فایل سرویس، در صورت هر کرش غیرمنتظره، سرویس به‌طور خودکار دوباره اجرا می‌شود.

## محدودیت‌های شناخته‌شده

- این ابزار برای یک ادمین طراحی شده (بدون مدیریت چند کاربر/نقش).
- در صورت ری‌استارت سرور، فایل‌های آپلودشده و وضعیت ارسال‌های در حال انجام از بین می‌روند.
